Customer API for adding custom functionality to websites and web apps with our Customer Portal.

**IMPORTANT**: this client is not compatible with the beta version of Customer API.
If you're still on beta, please consider updating your code to the latest stable version.
You can use @foxy.io/sdk prior to 1.0.0-beta.15 or a custom API client until you transition.

## Example

```ts
import { API } from '@foxy.io/sdk/customer';
import type { StoredSession } from '@foxy.io/sdk/customer';

const api = new API({ base: new URL('https://example.foxycart.com/s/customer/') });

// The API keeps the session in memory only. Save it to keep the customer signed in after a reload.
const saved = localStorage.getItem('customer-session');
if (saved) api.setSession(JSON.parse(saved) as StoredSession);

api.addEventListener('session', event => {
  if (event.detail) localStorage.setItem('customer-session', JSON.stringify(event.detail));
  else localStorage.removeItem('customer-session');
});

if (!api.session) await api.signIn({ email: 'customer@example.com', password: 'password' });

// Read the signed-in customer and their first page of subscriptions.
const customer = await api.get().then(response => response.json());
const subscriptions = await api.follow('fx:subscriptions').get().then(response => response.json());
console.log(customer.email, subscriptions.returned_items);
```

## Accessors

### session <MemberMeta type="StoredSession | null" href="/docs/reference/customer/types#storedsession" getter /> [#session]

A copy of the current session, or `null` when there is none. Changing the copy does not change the session. Use [`setSession()`](#setsession) for that.

***

### usesTemporaryPassword <MemberMeta type="boolean" getter setter /> [#usestemporarypassword]

When logged in with a temporary password, this property getter will return `true`.
Will return `false` if password reset is not required or if the session has not been
initiated, or if the session was initiated before the introduction of this feature.

### setSession()

```ts
setSession(session): void;
```

Replaces the session this instance uses, for example one saved from an earlier `session` event. `null` forgets the session without a request to the server. Throws a [`TypeError`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/TypeError) when the session is not valid. Does not dispatch `session`.

#### Parameters

| Parameter | Type |
| ------ | ------ |

#### Returns

`void`

### signIn()

```ts
signIn(credentials): Promise<void>;
```

Creates a Customer Portal session for a customer with the given credentials, keeps it in memory and dispatches `session` with it.
Incorrect email and password will trigger `AuthError` with code `UNAUTHORIZED`.

#### Parameters

| Parameter | Type | Description |
| ------ | ------ | ------ |
| `credentials` | [`Credentials`](/docs/reference/customer/types#credentials) | Customer email and password (one-time code). |

[`Promise`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise)\<`void`\>

***

### signOut()

```ts
signOut(): Promise<void>;
```

Ends the session on the server, then forgets it and dispatches `session` with `null`.

#### Returns

[`Promise`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise)\<`void`\>

***

### signUp()

```ts
signUp(params): Promise<void>;
```

Creates a new customer account with the given credentials.
If the email is already taken, `AuthError` with code `UNAVAILABLE` will be thrown.
If customer registration is disabled, `AuthError` with code `UNAUTHORIZED` will be thrown.
If the provided form data is invalid (e.g. captcha is expired), `AuthError` with code `INVALID_FORM` will be thrown.

#### Parameters

| Parameter | Type | Description |
| ------ | ------ | ------ |
| `params` | [`SignUpParams`](/docs/reference/customer/types#signupparams) | Customer information. |

#### Returns

[`Promise`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise)\<`void`\>
