import { MemberMeta } from '@/components/member-meta';

```ts
const client: API;
```

The shared checkout client. Every import of `checkout` or `checkout/loader` gets this same instance. The loader also sets its store, from the script's `?store=` or else the page's hostname.

Its type is [`API`](/docs/reference/checkout/types#api). It fires a non-cancelable `update` event whenever the resolved checkout state changes.

## Example

```ts
import { client } from 'https://cdn-js.foxy.io/sdk@2/checkout.js';

// Keep the session ID in a cookie. Do this before the store domain is set.
client.session.configure({
  storage: 'cookie',
  cookie: { maxAge: 60 * 60 * 24 * 30, sameSite: 'Lax' },
});

client.setStoreDomain('example.foxycart.com');

// Listen for changes to the cart.
client.addEventListener('update', () => {
  console.log(client.state, client.json?.items.length ?? 0);
});

// Add a product with a quantity and a custom option.
client.addItem([
  ['name', 'Mug'],
  ['price', '15'],
  ['quantity', '2'],
  ['color', 'Blue'],
]);

// Apply a coupon code from your own input.
client.applyCouponOrGiftCardCode({ code: 'SPRING10' });

// Later, when the shopper signs out, forget the session and reset the cart.
await client.session.end({ reset: true });
```

### addItem()

```ts
addItem(params): void;
```

Adds items the way an add-to-cart link or form does. `params` is the
link's query or the form's fields, in order. Repeated names and
HMAC-signed names (`name||hash`) go to the server untouched: the server
validates them, so this does not. `empty=reset` may be one of the pairs --
the server resets the session and then adds, in one request, which two
separate mutations could not guarantee (POSTs are queued, but a change sent
between the two could still land in the gap).

`session_id` and `output` are set by `postJson` and win over any pair with
the same name: the document that runs this owns the session.

Unlike its siblings, this dispatches no cancelable `item-add` event: the
caller already decided. The loader's add-to-cart cancelable event is
`foxy:add-to-cart`, dispatched before this runs, and on a store page
there is no cart item yet for `item-add`'s detail to describe.

#### Parameters

| Parameter | Type |
| ------ | ------ |
| `params` | \[`string`, `string`\][] |

#### Returns

`void`

### applyCouponOrGiftCardCode()

```ts
applyCouponOrGiftCardCode(params): void;
```

Applies a coupon code or a gift card code to the cart. The server decides which one the code is. An empty code adds an error message and sends nothing. Fires the cancelable `coupon-or-gift-card-apply` event first. If a listener cancels it, nothing is sent. When the side cart is mounted, the call goes to the side cart and this client fires no events. If the request fails, the client adds an error [message](/docs/reference/checkout/types#message) to `json.messages` and calls `onError`.

### session.start() [#session-start]

```ts
start(id?): Promise<void>;
```

With an `id`: adopts it. The ID is stored first, because the merchant
owns it, so it stays stored even if its cart then fails to load.

Without: creates a new, empty session. The old ID is replaced only once
the new session exists. The old cart is not reset on the server.
